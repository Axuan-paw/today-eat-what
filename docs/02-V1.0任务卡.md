#### 小步 4-3 · 主函数 `recommend()` + 惊喜分支（1.5 小时）

```js
async function recommend(profile, dishes, opts = {}) {
  // 写成 async 是故意的：V3.0 换成 LLM 时这里会真的等网络
  const history = opts.history || state.history || [];
  const exploreRate = opts.exploreRate ?? 0.15;

  // 第 1 步 · 硬性过滤（用 4-1 的 mergeAvoid）
  //   得到候选池 pool（已剔除忌口菜）
  //   若 pool 为空 → 放宽预算再试；仍为空 → return { dish:null, source:"none", strategy:"fallback" }

  // 第 2 步 · 掷骰子决定走哪条分支
  //   const isExplore = Math.random() < exploreRate;

  // 第 3 步 · 利用分支（exploit）：
  //   取最高分；并列 >=2 道 → 随机取一道   strategy: "exploit"

  // 第 4 步 · 探索分支（explore）：
  //   a. 从 pool 里剔除 history 中出现过的菜 → 得到 fresh
  //   b. fresh 为空 → 退回利用分支（strategy 改回 "exploit"）
  //   c. 否则在 fresh 里取一道（可以取分数中上的）
  //      strategy: "explore"

  // 第 5 步 · 返回
  //   { dish, reason, source: "rule", strategy, debug: { score, hits } }
}

function buildReason(hits, strategy) {
  // strategy === "explore" → 用不同的文案，例如：
  //   "换换口味：你有段时间没吃这个了"
  // strategy === "exploit" → hits 前 2~3 条拼接
  // hits 为空 → "随机为你挑选，试试新口味"
}
```

**⚠️ 绝对约束**：探索分支**只能在 `pool` 内部选**（`pool` 已经过滤掉忌口）。**任何情况下都不能为了"惊喜"推出忌口菜。**

**做到什么程度算过**：见【验收标准】。

**【卡住了先看这里】**
- `??` 不认识？它是"空值合并"：`a ?? b` 意思是 a 是 null/undefined 时用 b。等价于 `a != null ? a : b`。
- 不知道怎么验证探索分支？把 `exploreRate` 手动写成 `1`（100% 走探索）测一次，再写成 `0` 测一次，就都覆盖了。
- `history` 里的菜名对不上？`state.history` 存的是菜名字符串数组（如 `["麻辣烫","沙拉"]`），直接用 `history.includes(dish.name)` 判断。

---

### 【决策点】

| 决策 | 选项 A（推荐） | 选项 B |
|---|---|---|
| 超预算的菜 | **先降权（-15 分），全部超预算时才放宽** | 直接否决 → 预算填低了会一道菜都推不出来 |
| 分数并列 | **随机取一道**，保留"抽"的乐趣 | 固定取第一道 → 每次都推同一道，体验差 |
| 无偏好时 | **全部 0 分 → 退化为随机**，这是正确行为 | 强行推第一道 |
| 探索比例 | **默认 0.15**（约 6 次里 1 次） | 调高到 0.3 → 更常换口味，但可能推出明显不爱的菜 |

### 【验收标准】
1. 设「菜系=川湘、口味=辣、目标=减脂、忌口=香菜」→ 结果是川湘、不含香菜、热量 ≤ 400
2. 本人忌口填一个菜单里确实有的食材 → 连点 20 次，永不出该食材
3. **添加搭子「小明:香菜」→ 连点 20 次，结果永远不含香菜**
4. **把 `exploreRate` 改成 1（强制探索）→ 结果仍不含任何忌口**
5. 预算填 1 元（低于所有菜）→ 仍返回结果，不返回 null
6. 清空所有偏好 → 结果近似随机（多跑几次会变）
7. `debug.hits` 能看到命中了哪几条；`strategy` 能看出走的哪条分支

### 【成本预估】
**3 小时**（比第一版多 1h，因为多了 5 条打分规则 + 探索与利用分支）。
**最大的坑**：① `null` 参与数值比较（上面标了大坑）；② 探索分支忘了只用过滤后的候选池。
