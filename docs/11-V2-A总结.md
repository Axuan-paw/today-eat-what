## 五、指令拆解 —— 正面回答"我还是搬运工"

这一段是本次总结的**重点**。下面六条是 V2-A 出现过的指令，每条讲清"每个部件在干什么"。**能自己复述这六条，你就不再是搬运工了。**

### 1. `main:app` 里的冒号 —— 最该记住的一条

```powershell
.venv\Scripts\python.exe -m uvicorn main:app --reload --port 8000
                                ^^^^^^^^^
```

- `main` = 文件 `main.py`（不带 `.py`）
- `app` = **那个文件里的变量名**，也就是 `app = FastAPI()` 那个 `app`
- `:` 读作"的"——**"main 模块的 app 变量"**

uvicorn 拿到这个地址，就去找 `main.py`、导入它、取出 `app` 这个对象，然后让它接管 HTTP 请求。

**为什么这条最重要**：V2-C 要把接口拆成 `app/routers/dishes.py` 时，启动命令就变成 `app.main:app` 或 `main:app`（视目录而定）——如果你不知道冒号两边是什么，那一刻就只能靠试错。**知道了就只是改个字符串。**

> 顺带反证：为什么不能写 `main:main`？因为文件里没有叫 `main` 的变量。你写错时 uvicorn 的报错就是 `Attribute "main" not found in module "main"`——**报错信息读懂了，这类问题全部自愈**。

### 2. `-m` 是什么

`python -m X` = **把 X 当成一个模块来运行**。

- `.venv\Scripts\python.exe -m pip ...` 等价于跑 `pip`，但**用的是这个 python 自己的 pip**
- `.venv\Scripts\python.exe -m uvicorn ...` 同理

**为什么必须加 `-m`**：因为你没激活 venv（见第 3 条），PATH 里没有 venv 的 `Scripts` 目录，直接敲 `pip` / `uvicorn` 会找不到命令、或者用到全局那份。`-m` 是"我明确指定用这个 python 来找"。

### 3. 为什么到处写 `.venv\Scripts\python.exe` 全路径

**venv 的"激活"（`Activate.ps1`）作用只是临时改 PATH**，让人能直接敲 `python`。它被 PowerShell 执行策略拦住了，所以走全路径。

两种方式**结果完全一样**，只是全路径更啰嗦、但更稳：

| 方式 | 效果 | 风险 |
|---|---|---|
| 激活后敲 `python` | 用 venv 的 python | 忘了激活 → **静默用全局**，装错地方 |
| 全路径 `.venv\Scripts\python.exe` | 用 venv 的 python | 无（就是要多打字） |

> **这就是"为什么全路径"的全部秘密**：不是 venv 必须这么用，是为了**避免"忘了激活"这个静默错误**。宁可啰嗦，不要静默出错——这是个值得记住的工程取向。

### 4. `-i` 是什么

```powershell
.venv\Scripts\python.exe -m pip install -i https://mirrors.aliyun.com/pypi/simple/ fastapi
                                     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
```

`-i` = `--index-url` = **去哪个"包仓库"取货**。默认是 `https://pypi.org`（国外，你这边慢/不通）。换成阿里云镜像就是从国内镜像站拿同一份包。

**它和 `-m` 的区别**：`-m` 决定"用哪个工具"，`-i` 决定"这个工具去哪取货"。两个独立的事。

### 5. `git mv` 和普通 `Move-Item` 的区别

| 做法 | git 记录成 | 后果 |
|---|---|---|
| `Move-Item` + `git add` | 删除 1 个 + 新增 1 个 | 该文件的历史**断了**（`git log` 追不到旧改动） |
| `git mv` | **重命名** | 历史连续（本次显示 `R100` = 100% 相似度） |

**相似度是怎么算的**：git 不比文件名，比**内容**。内容一模一样就是 `R100`；如果你搬家的同时改了 3 行，可能变成 `R97` 之类，git 依然认得出这是同一个文件。

### 6. `$env:all_proxy=""` 为什么这么写

`$env:名字` 是 PowerShell 读写**环境变量**的写法。`=""` 是赋空值，等于"清掉"。

环境变量的特点：**它是给"子进程"看的**。你在终端清了，从它启动的 pip / python 才看不到死代理。

> **所以它必须每个新终端重做一次**——环境变量是**进程级**的，父进程（系统）里那份还在，新开的终端会重新继承。
