## 一、大方向

### 一句话

**V2.0 = 把数据从浏览器搬到数据库，把逻辑从浏览器搬到服务器。**

### 为什么做（对项目负责人而言）

| 理由 | 说明 |
|---|---|
| **简历硬通货** | "全栈 + 数据库 + REST API"才是技术岗简历真正被搜的词。V1.0 是纯前端，分量不够 |
| **课程落地** | MySQL、Java Web 学过的东西，在这里第一次真正用上 |
| **为 V3.0 铺路** | LLM 的 API Key 绝不能放前端 → 必须有服务端。V2.0 就是在造这个服务端 |

### 终点长什么样

```
浏览器（frontend/）          服务器（backend/）           数据库（MySQL）
┌──────────────┐            ┌──────────────────┐        ┌─────────────┐
│ 界面（不改）   │  HTTP      │  FastAPI          │ SQL    │  dishes     │
│ store() ─────┼───────────▶│  /api/dishes      │───────▶│  tags       │
│              │            │  /api/profile     │        │  dish_tags  │
│ recommend()  │            │  /api/recommend   │        │  ...        │
│  （暂时仍在    │            │                   │        │             │
│   前端）      │            │  规则引擎（搬过来）  │        │             │
└──────────────┘            └──────────────────┘        └─────────────┘
```

**关键约束（来自 V1.0 的设计）**：前端 `store()` 接口的**签名早就定死了**（`load` / `save` / `addDish` / `removeDish` / `updateProfile` / `pushHistory`）。
V2.0 只换它的内部实现（`LocalStore` → `ApiStore`），**界面层一行都不改**。

## 三、环境体检结论（HP 实测，2026-10-12）

| 项目 | 实测结果 |
|---|---|
| Python | ✅ **3.14.0** + pip 25.2 |
| MySQL 服务 | ✅ **MySQL80 正在运行**（自动启动） |
| MySQL 客户端 | ✅ 8.0.44，`mysql` 命令可用 |
| SQLyog | ✅ 已安装 |
| **代理环境变量** | ⚠️ **`all_proxy` / `http_proxy` 指向 `127.0.0.1:30810`，但该代理没有可用节点** → 导致 pip / curl 等工具静默失败 |
| 清华 PyPI 镜像 | ❌ **403**（当前网络访问不了） |
| 阿里云 PyPI 镜像 | ✅ 200 |
| 腾讯云 PyPI 镜像 | ✅ 200 |
| 官方 PyPI | ⚠️ 可达但**很慢**（拉一个索引页 11 秒） |
| FastAPI / uvicorn / pymysql | ❌ 均未安装 |
| **Python 3.14 兼容性** | ✅ **已实测**：`pip --dry-run` 能完整解析 FastAPI 全家桶（含 `pydantic_core-2.50.0` 这类 Rust 扩展包，说明 3.14 的预编译 wheel 已就绪）→ **可以放心用 3.14，不需要降级** |

### 由此得出的两条硬建议

1. **装包时用阿里云或腾讯云镜像**，别用清华源（403），也别裸连官方源（慢）
2. **不要装 `uvicorn[standard]`** —— 它会拉 `httptools` / `watchfiles` 等 C/Rust 扩展，在 Python 3.14 上极可能编译失败。**只装 `uvicorn` 本体即可**（纯 Python，功能足够开发用）

## 四、V2-A 准备工作清单

```
1. 处理代理环境变量（否则 pip 永远失败）
2. 建虚拟环境 venv（不要污染全局 Python）
3. 用阿里云镜像安装依赖
4. 验证 uvicorn 能跑起来
```

**Python 版本结论（已实测）**：**3.14 可以直接用，不需要降级。**
唯一的注意点：`uvicorn[standard]` 会额外拉 `httptools` / `watchfiles` 这类 C/Rust 扩展（**本次没测**）。**开发阶段用纯 `uvicorn` 就够了**，别带 `[standard]`。

## 五、需要项目负责人拍板的三个决策点

| # | 决策 | 选项 A（推荐） | 选项 B |
|---|---|---|---|
| 1 | 数据库选型 | **MySQL**（环境已就绪、课程学过、简历常见） | SQLite（更简单，但简历分量略低） |

| 3 | 前端何时拆分 | **V2-A 就拆**（`frontend/` + `backend/` 一次到位） | V2-E 再拆（改动集中，但那时要动更多文件） |

**HP 的建议是全选 A**，理由已写在表格里。
